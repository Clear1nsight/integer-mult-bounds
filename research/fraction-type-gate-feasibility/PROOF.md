# Entry-domain proof before complete construction

Sources: original Ali Romman Fraction trace at the exact source hashes in table_parent.py; complete PR5848 head 66fb6c6b8683b37967e9d7f313b3df99a49d2406; predecessor table df9dc4c89b31494f1390d16b9ca2a15e5946e853. Standard Python 3.12 Fraction arithmetic is retained, with the independent integer engine unchanged. New entry gate prepared for Chris R / Clear1nsight with substantial OpenAI Codex assistance. Apache-2.0.

The gate inspects only exact built-in containers and member types, using identity (is) for every type alternative. Tuple membership/equality on type objects is deliberately excluded because a foreign metaclass can define equality. Before using dict lookup, it requires all word keys to be exact strings. Before iteration/indexing of program/events, weights/rows and rounded values, their container types must be exact list/tuple or set/frozenset. Public/owned counts are exact ints; event fields are exact str/int/bool/Fraction; the first two members of every supplied weight pair are exact standard Fractions. Malformed roles, strings and short/missing weights are not proactively parsed or repaired. They retain the original trace's outcome. Other domains use the predecessor checked method; no custom method is invoked by the entry gate.

Assume inputs and the frozen runtime remain stable during a trace, as required by the source qualification. Initially each row is empty. INIT and CLEAR replace it with another empty row. Every rounded injection inserts F(1). SCALE sets q=F(scalar), then replaces each row coefficient by q*v. ADD/COPY also construct q with F; the destination default old is F(0), while the induction hypothesis gives an exact F source coefficient v. Standard F addition and multiplication of exact F operands yield exact F results. Removing zero coefficients does not introduce values. Thus old,q,v always have exact F type whenever the contribution method is called, and weights a,c are exact F by the entry gate. The four computed results are exact F as well. The canonical five-value key and miss computation are unchanged from the predecessor, and successful cached results remain immutable F tuples. Hence the per-update all(type(x) is F...) test can be omitted for this domain.

The selection is per freshly created trace table. Zero capacity uses the original checked path. An explicit recertification replaces the selected method in either direction, so a failed second certification cannot retain a trusted method. Each independently executed backend and each trace receives a new table; there is no shared answer cache. No score update, rounded event, row change, peak/witness, signed hash or original comparison is removed.

The finite gate retains the unchanged predecessor's 241 programs at four capacities, 964 complete comparisons and all 34 controls. New controls verify that all ordinary fixtures select the intended domain, subtype/foreign-value fallback and observable custom-method order match the original trace, exact operand/result types hold on mixed-operation controls, malformed outcomes agree, and recertification/disabled capacity behave correctly. These are supporting finite checks, not a universal proof of arbitrary Python object semantics or concurrent input mutation. The gate is an optimization domain with fallback, not a new accepted input requirement.

No complete qualifier or performance claim is admitted by this proof. The next gate is one full actual trace equality audit and a complete-cost screen including all new finite controls. Insufficient 15% wall/CPU headroom stops construction.

Static final review found that the initial type-alternative tuple membership could call foreign metaclass equality. METACLASS-REVIEW.json preserves an actual non-arithmetic probe, the initial predicate is retained, and two new controls reject custom equality calls for foreign containers and scalars. The identity-only final predicate is verified normally/optimized and gets a separate full actual audit; both earlier and final source-bound observations remain, with no sample discarded.
